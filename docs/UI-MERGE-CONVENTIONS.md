# 合并修改时的界面约定

本项目的现有 Apple 玻璃界面是后续合并和新增页面的基准。功能来自外部 PR 时，也应适配本项目已有控件、排版和交互。

- 页面优先使用 `PlatformPageFrame`、`BetaGlassScrollBody` 和现有导航结构；按钮、下拉、分段、提示与加载复用 `shared/widgets` 中对应实现。
- 不将默认 Material 芯片、圆形进度环、下拉菜单直接混入 Beta 界面。已有 Cupertino 滑块和开关可继续使用；主题颜色从当前主题读取。
- 选择样式时用生产渲染器提供实际预览，避免为预览复制另一套效果。演示数据须明确标注，不写入真实听歌统计。
- 动画应可中断、遵循减少动画设置，并在不可见、收起和后台时停止无用的持续 Ticker。预览包含循环动画时，主机测试采用有界逐帧推进。
- 保留当前歌曲页收藏按钮位置。歌曲总收藏数属于官方歌曲聚合数据，与用户本人的收藏状态和同步操作分开处理；缺失时不填零或伪造数值。
- 列表优化要验证用户下滑后的实际构建批次、旧行状态和排序，而不以网络分页条数代替界面行为验收。
- 更新抽屉的进度、状态文字与操作按钮位于同一固定区域；长更新说明单独滚动。

交付前检查深浅主题、窄屏和大字体，以及按下取消、加载、失败和减少动画状态。Flutter 主机渲染不能替代 Android 玻璃 GPU、真实音频和账号业务验收。
