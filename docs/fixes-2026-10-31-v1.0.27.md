# Mesting Music 1.0.27 / Android code48

本版基于本机 1.0.26 工作源码，落实用户确认的记录兼容、单条脱敏诊断与 Tab 反向调整。原签名、定制 Release 引擎、完整玻璃、双平台浏览/封面缓存及已移除登录插画的状态保持。

## 一起听结束记录与私信

私信读取此前声明 Android 9.0.65，用户反馈仍收到“当前版本无法显示该信息”。本版将这两个只读接口的 appver、versioncode、osver 与 User-Agent 统一为公开互操作参考中的 9.5.61，定义集中在 `netease_message_protocol.dart`。这是一项兼容调整，尚未凭真实消息证明它是全部根因。保存的账号身份、私信发送与其他请求保持原有逻辑。

已发现的本地解析缺陷是：解析器支持的 extra、payload、record、report 等消息容器，在 `NeteaseChatMessage.parse` 的入口处曾被丢弃。本版使用同一字段清单保留历史消息和会话预览中的消息内容；补充多层 JSON 解码，旧兼容提示不再覆盖现代正文。解析限制深度/节点/字符串大小，不遍历发送者和接收者资料，不根据一句兼容提示或孤立 roomId 生成记录，不从本次用户海报写入固定歌曲数、时长或详情链接。

仍无法识别的兼容提示下提供“导出此条诊断”。点击后先预览，用户再次点击“复制诊断”才写剪贴板。报告仅含匿名化字段路径、数据类型、有限消息类型码、长度和是否有官方网页目标；不含正文、用户/房间/记录 ID、昵称、头像、Cookie、令牌或链接值。未知字段名也匿名化。没有自动上传、额外接口请求或批量聊天导出；切换账号后旧对话框不可复制。自动调试日志仍关闭。

## Tab 过渡

按用户对 1.0.26 的实际反馈对调方向：发现→音乐→音乐库→我的时，新页面从右侧进入、旧页面向左退出；反向时新页面从左进入、旧页面向右退出。继续使用两页共享的真实入场进度，保留原曲线/时长、快速点击的最终目标、减少动态效果和详情返回逻辑。

## 验证界限

最终结果见 `validation-2026-10-31-v1.0.27.json`。私信测试包含解密后的实际传输契约、边界容器、多层 JSON、正文优先级、无法解析时保留提示，以及诊断的预览/取消/复制、脱敏、容量限制和账号变化；使用合成夹具，没有取得用户原始消息。

Tab 在实际声明式 Navigator 替换的半程检查四页每个相邻方向与跨页跳转、新旧页一屏宽衔接、快速调度及减少动态效果。UI 使用生产聊天/详情/诊断组件进行主机渲染，并覆盖 320 宽、140% 文字。

本次没有访问手机/ADB、真实账号或后台，没有安装、提交推送或发布。用户这条真实记录是否已恢复以及官方详情网页的手机表现，必须保留为安装后验收，不能把模拟回归通过写成真实记录已修复。
