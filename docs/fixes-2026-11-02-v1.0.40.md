# Mesting Music 1.0.40 / Android code61

本版按用户确认修复搜索与底部控件、网易云用户操作、一起听结束记录和深色未读徽标，并调整冷启动内容加载时机。仅在 `D:/AnLi` 准备本地原签名交付；没有访问手机、真实账号或后台，没有提交推送或发布。

## 搜索、底部控件和冷启动

搜索胶囊外侧点击改由当前 `EditableTextState.requestKeyboard()` 请求输入法，覆盖 Android 收起键盘但输入框仍持有焦点时再点边缘无效的情形。收拢与展开使用同一棵编辑器，过渡中不叠放两个输入框。

新增 `BetaMusicChromeScope` 注册实际覆盖页面，绘制、触摸与辅助功能共同遵守覆盖状态。完整播放器和自带输入区的页面不再仅依赖 GoRouter 地址隐藏底栏；通过 `Navigator.push` 进入的播放器也登记。播放器收起仍跟随原有 reveal 信号，保留完整玻璃与退出动画；离屏保留页不占用当前页的底部控件。

系统文本菜单跟随层会保留打开时的字段偏移。搜索胶囊随键盘/宽度变化移动后，原自定义菜单再次叠加全局位移，可能越过屏幕边缘。菜单锚点与可见区域现转换到同一跟随层坐标，短时跟踪移动后停止，保持菜单宽高约束和输入框上方间隔。

`BetaEntranceReadiness` 和 `RouteSettledContent` 让冷启动的我的页面、搜索可选探索货架在所在 Tab/搜索进入动画完成后开始挂载。搜索历史与热词仍可立即使用；已访问页面保持挂载。软件回归记录冷内容在移动阶段挂载0次、落地后挂载1次、重复切换仍为1次；这不是手机帧率、GPU或长期流畅度实测。

## 网易云用户与徽标

原用户搜索调用 `/follow`，实际轻量路由链没有分派该路径；现接入既有 follow/delfollow weapi 契约。测试使用真实 `NeteaseApi` 和固定测试加密器解密验证传输，生产编码器仍使用原随机机制。

搜索用户头像/名字已有个人主页入口。已用生产 appRouter 验证明暗模式、直接搜索路由及从我的底栏展开搜索，点击进入根 Navigator 的可见主页、页头返回后保留查询/分类。主机没有复现用户手机上的无法进入；本版壳层修复后的真实手机行为仍待用户验收，不将其单独归因于关注接口。

共享未读徽标采用红底白字，保留0隐藏、99+上限与语义标签；明暗模式小字对比度均超过4.5:1。

## 一起听结束记录

本次阅读本地官版9.6.15的 CommonMessage 解析和默认链接配置，并检查官版公开记录网页脚本。私有研究保存在 `.codex-artifacts/2026-11-02-v140-fixes/`，原始官版包、脚本及用户截图不会打入公开源码包。

- 普通双人报告使用 `/api/listen/together/record/get`，参数 `roomId`。
- 全部记录使用 `/api/listen/together/full/records`，保留 `{page:{size:50,cursor}}`、`hasMore/nextCursor` 与账号权益字段。
- 房间歌曲另读 `/api/listen/together/room/songs/list`，只在用户点收藏后取得，不在打开报告时发起收藏。
- 本次和累计 `duration/totalDuration` 都是毫秒，与正在进行的房间统计不同；歌曲数分别读取，距离已为公里。缺失值明确显示暂未提供。

消息解析新增官版 `mp.music.163.com` 精确主机与普通双人 ending 路径识别，解包受限 JSON/网页包装，取得房间标识后进入原生报告。普通双人结束卡片显示红底、双方头像及消息明确提供的时长。缺少房间标识的旧消息保留已有详情并提供全部记录入口；无法识别的 `[分享内容]` 也可手动预览脱敏结构诊断。

原生流程为聊天卡片 → 和TA的一起听 → 全部记录 → 某次报告。详情有聊天、再次邀请、歌曲数、本次时长、双方距离和独立累计统计；邀请仅在用户点击时进入原有房间流程。收藏先选择并验证本人普通歌单，再作一次批量写入；不自动重试不明结果。分享报告调用现有系统文字分享，包含真实统计和官方记录链接，不自动向好友发送消息。

非会员按官版可见边界隐藏末条记录与最常好友累计统计，不用本机时长补齐。多人记录与双人接口不同，本版历史中明确提示在网易云查看多人记录，避免误用双人接口。没有实现会员购买或虚构缘分报告。

官版网页声明 GET+encrypt，通过原生桥接发送；静态脚本不能证明其实际线传输方法。本工程沿用现有 EAPI 只读适配，合成请求/返回测试不等于真实账号读取得到同样结果。用户此次私信的原始 DTO 未取得，仍不能把已修的兼容缺口说成该条私信的唯一根因。
