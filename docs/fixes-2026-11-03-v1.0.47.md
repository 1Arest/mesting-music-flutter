# 1.0.47 / code68 实现与验证

本版按已确认范围处理整个 App 的长列表，并修正听歌足迹横向切换和酷狗收藏顺序。完整入口清单与接口限制见 [长列表矩阵](LONG-LISTS-2026-11-03-v1.0.47.md)；安装检查见 [安装验收](INSTALL-v1.0.47.md)。1.0.46 的底距、提示、搜索、下载暂停和校验续传继续保留，原说明仍单独保存。

`TrackPage` 显式传递来源游标、总数与后续页状态。`FavoriteTrackWindow` 和 `PlaylistDirectoryWindow` 将分批浏览与完整集合操作分开：首批通常为 30 条，接近末尾时续载；刷新保留已浏览范围，失败保留旧内容。网易云歌单先取得有序 ID 索引，再补本批详情；游标依据来源消耗量前进，不能用去重后的可见行数推算。歌手、酷狗普通歌单等支持分页的入口使用真实接口页参数。

固定响应保持完整接收，但大 JSON 解码、缓存复制、歌曲快照转换和部分统计转到 worker；页面分批显示，避免进入后创建全部行。`background_json.dart` 使用有上限的估算选择后台处理，不能先在主线程完整编码后再判断。通用结果、评论、消息、记录和歌单网格改用惰性构建；本地音乐分组/查询、历史聚合和消息派生结果复用不可变快照。缓存和异步结果继续遵守账号、凭证和请求代次边界。

完整收藏状态、收藏总数和浏览窗口独立。收藏内搜索覆盖完整当前账号收藏；播放全部、整份下载及排序仍显式取得完整集合。下载任务结构变化与单行字节进度分离，批量加入/取消合并持久化；大目录恢复完成前防止新任务覆盖旧记录。暂停、删除和校验后的断点续传仍由原生命周期管理。

听歌足迹将公共标题、累计时长及周/月/年分段栏放到横向 pager 外，只移动下方报告。公共头部仍参与竖向收起，各尺度保留日期区间和滚动状态。酷狗喜欢使用真实 `collecttime` 全局最新优先排序，兼容秒/毫秒并保持同时间来源顺序。所核私人接口没有已确认的倒序参数，因此喜欢首次建立完整记录索引；普通歌单仍分页。缺少真实收藏时间时保留来源顺序，不猜测收藏先后。

Beta 145 个文件 1729 项通过、2 项条件跳过，是首轮全量与成功整文件复跑的合并结果，每文件只计一次。Stable 6 文件 63 项、独立导航整文件 54 项通过；正式关闭诊断后的 28 项包含在 Beta 对应文件中，不重复累加。分析 0 问题，最终 26 帧主机渲染在两轮内核对完成。大集合夹具包含 3000/10000 条数据、末尾搜索、来源游标缺失详情、账号失效、全局收藏时间排序及滑动中公共头部坐标。R4 原生 16 项为相同输入的继承结果，本版实际 Android 构建另行完成。
