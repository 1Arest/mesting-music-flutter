# 八场景渲染实验室

入口：设置 → 流畅度诊断 → 八场景渲染实验室。

本实验使用固定的合成列表和向量封面，不读取账号、歌单或真实歌曲。
它与原有的真实页面连续巡检独立记录，可运行当前场景或依次运行八个场景。
建议比较前手动暂停音乐；实验不会切换账号或主动播放歌曲。

| 场景 | 比较目的 |
|---|---|
| 静止背景 / 单玻璃 | 静态参照，空闲时可能没有新帧 |
| 滚动背景 / 单玻璃 | 背景变化时的实时处理 |
| 滚动背景 / 双玻璃独立 | 两个独立表面的处理 |
| 滚动背景 / 双玻璃共享 | 共享同一背景和相同滤镜 |
| 共享背景 / 不同滤镜 | 与同滤镜共享路径交叉比较 |
| 滚动背景 / 重叠玻璃独立 | 重叠表面保持独立读取 |
| 菜单尺寸形变 | 连续改变遮罩几何的成本 |
| 双页面滑动过渡 | 新旧内容并存时的绘制成本 |

每段先完成布局和预热，再执行固定动作。滚动为340逻辑像素、250ms一次，
六组往返；形变/切页分别采用340ms前进、310ms返回。系统减少动态效果设置
仍受尊重并写入报告。菜单与切页是最小合成复现，不代表所有生产菜单或快速连点路径。
向量封面不测量真实位图解码/上传。

停止、退出页面或退到后台会取消后续动作。已拥有的采集仍等待末批帧收齐，
然后释放诊断状态。运行期间抑制自动签到/奖励，与已有诊断约定一致。

完成后可以导出本轮JSON。每个场景独立保存，最多八段；取消或失败使用固定状态，
不导出原始异常、账号、歌曲、任意路径或网络响应。新报告使用独立固定文件，
不会覆盖真实页面巡检报告；原生分享桥只接受该文件并限制为16MiB。

`completed`仅表示动作完成。报告同时记录构建模式、shader支持和请求的渲染后端；
请求值不证明原生后端已经核实。主机/Debug结果是结构验证，FrameTiming不是GPU
执行时间或屏幕FPS。诊断入口和PR合并不代表主要滑动卡顿已经解决。

维护结构：

- `core/diagnostics/glass_lab_run.dart`：固定目录、取消票据、采集所有权和逐段编排。
- `core/diagnostics/glass_lab_store.dart`：有界、独立文件保存。
- `features/settings/presentation/glass_lab_scene.dart`：无业务依赖的合成场景。
- `features/settings/presentation/glass_lab_page.dart`：控件、生命周期与动作驱动。

当前Beta Release使用固定的Impeller/OpenGLES引擎路径。采用Profile工具或其他宿主
复测前，需要核实实际后端和配置。最终性能结论应回到完整视觉和真实页面实机对照。
