# 播放与曲库工具

## 入口和默认行为

- 设置 → 播放设置：复用现有 Apple 分组卡片、Cupertino 开关／滑杆和玻璃滚动容器。设置独立存储在 `music_playback_preferences_v1`。
- 下一首提前准备默认开启，适用于所有网络。歌曲剩余 30 秒时最多准备一个可确定的待播项，原有手动点播／暂停逻辑继续拥有优先级。关闭该项后，开启交叉淡化仍会在临近结束时准备必要的下一首。
- 音量平衡默认关闭。交叉淡化默认关闭，开启后默认 3 秒，可选 1～6 秒，仅自然结束时使用。
- 下载管理 → 下载任务 → 批量管理：全部暂停、全部继续、重试失败任务。失败分类为网络、存储、登录／授权、音源和其他；重试遵循当前失败筛选，暂停和继续覆盖当前账号的任务。
- 搜索 → 歌曲 → 版本筛选：全部、原版、现场、翻唱、伴奏、未知。只筛选已加载结果，保留继续加载入口；查询变化时复原筛选。
- 自己的歌单 → 管理 → 歌单体检：本地歌单及支持管理接口的酷狗／网易云歌单可使用。完整读取歌单后，展示疑似重复、本地文件不可读、已有不可播提示。用户选择并确认后只移除歌单关联；收藏和文件保留。汽水的专用歌单页尚无此入口。

## 播放模块与边界

`playback_preferences.dart` 仅负责校验和串行保存偏好。`playback_transition.dart` 持有最多一个静音准备解码器和一个短暂退出的前驱，`prepared_playback.dart` 是它与现有音频所有者、逻辑队列之间的适配层。所有媒体会话、历史、队列和音效仍由 `MestingAudioHandler` 管理。

预准备解析结果以队列、品质及操作代次约束，过期结果不绑定到当前歌曲；准备阶段不发布播放歌曲、不消耗队列、不记入收听。远程准备使用原生缓冲，目标时间 4～8 秒、目标数据量 2 MiB；已有完整缓存或本地文件优先使用。平台音源解析本身可能有网络开销；不对所有平台承诺严格的总流量上限。音源解析／准备失败时保持当前歌曲，正常切歌流程负责重试。

交叉淡化在下一首解码器真正前进后才交接媒体身份，再按等功率包络重叠播放。身份发布与解码器切换同步，避免慢输出路由操作与新 Seek 竞态。即将结束的歌曲通过独立完成事件记一次，自然完成不会再跳过已进入的下一首。过短或时长未知的下一首不叠播。手动上一首／下一首、点播、拖动、暂停、账号／队列变化会使过时包络失效；停止前驱并等待最后的音量调用结束后恢复当前解码器正常音量。一起听、单曲循环和定时停止场景不叠播。媒体输出偏好在静音准备与退出前驱之间继承，均衡器观察当前会话 ID。

当前实现准备逻辑队列中已经确定的下一项；没有待播项、必须临时请求推荐续播时沿用原有加载流程。原生准备的网络缓冲不等于一首歌已经下载到下载目录。

## 音量平衡

Android 音乐所有者的 Media3 PCM 处理链，在汽水音效之前加入 `MusicLoudnessProcessor`。`TrackLoudnessMeter` 是独立的纯 Java 数值模块，支持单声道／双声道 PCM16 和 float：K 加权、400ms 窗口、100ms 步进、绝对 -70 LUFS 与相对 -10 LU 门限，目标 -16 LUFS。增益限制 ±12dB，同时用已观测样本峰值保留 2dB 余量；不宣称获得真峰值认证。应用的是整首固定增益，不是动态压缩器，也不调整系统媒体音量。

仅在开启时测量解码数据。完整、未 Seek、覆盖时长 98%～102% 且至少 10 秒的音频在 EOS 后生成本地结果。首次／无可靠结果时使用原音量，后续重新加载该录音时使用固定增益。中途启用、跳播、数据不足或静音不会产生臆测的增益。身份摘要包含歌曲来源、ID、实际品质、码率和时长，不保存音频、原始 URL、凭据或上传分析结果。最多缓存 1000 条增益，未知格式直接旁路。当前接入面向项目的 Android Beta 音频输出链。

## 体检与版本证据

重复检查要求歌名（保留版本词）、歌手和已知时长接近，提示为疑似，用户决定保留哪一份。文件不可读也可能表示目录授权改变，不等价于文件永久丢失。不可播提示仅来自已保存且明确受限的平台信息，可能随权限改变；没有播放 URL、试听、未解析、断网或登录过期均不视为歌曲已失效。体检不批量探测远程音频或下载全曲。

搜索“原版”需要平台作品／录音信息；缺失信息归为未知。现场／伴奏标记只从录音标题读取，不以歌手姓名包含 Live 等文字推断。筛选不会合并不同版本或把平台未提供的信息伪造成确定事实。

## 验证和真机验收

新增测试覆盖偏好恢复、版本筛选与重置、疑似重复和受限证据、批量下载的账号隔离、大字号／深浅色设置、移除确认、静音准备不计收听、队列变化拒绝旧解析、自然重叠、完成事件、慢路由交接与 Seek 竞态、暂停、定时和一起听边界。沿用音源刷新、暂停淡出、完成门控、定时、下载续传、下载页、作品识别及经典歌单／搜索测试。

纯 Java 测试 `third_party/just_audio/package/test/android/TrackLoudnessMeterTest.java` 可与测量器一同用 javac 编译后运行，覆盖 44.1／48／96 kHz、不同输入音量的一致目标、静音、不完整录音和瞬态峰值限制。Android 插件全部 Java 源码另用项目固定的 Media3 1.9.2、Android 36 和 Flutter embedding 编译校验。

合并／发布前仍需真机听感和系统行为验收：不同音乐平台、移动网络／弱网、蓝牙／有线输出、锁屏／后台、一起听、系统打断、均衡器和汽水音效组合。当前自动测试没有输出实际可听音频，未据此宣称无缝播放或主观听感已验收。
