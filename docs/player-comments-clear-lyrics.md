# 播放器评论动效与清晰歌词

## 评论为什么从右侧出现

播放器封面上拉已正确调用评论入口，但 openPlatformSongComments 仍创建普通 MestingPageRoute。当前音乐界面的全局 BetaPageTransitionsBuilder 会让这条普通路由从右侧进入；原有手势测试只检查是否打开，未验证运动方向。

播放器入口现在显式标记 fromPlayer，使用独立 PageRouteBuilder 绕过普通横向切页主题：从底部升起，返回时向下收回。原播放器停留在原位，不横移。保留评论整页、根 Navigator、原歌曲与账号边界、系统返回，以及普通列表/歌单等入口原有的横向路由。系统关闭动画时使用零时长，玻璃背景仍使用实时页面而非路由快照。

## 第三种歌词样式

在“装扮 → 我的风格 → 歌词”中追加“清晰歌词”预览卡片，保持 current、focus 两个既有选项的保存标识及默认行为。

- 参考提供的网易云截图，采用居中排版、较克制的默认 20 字号、当前句高亮与其余句降低亮度。
- 保留上下边缘淡出；关闭歌词文字的模糊和非当前句缩放。播放器原有封面背景效果不变。
- 使用现有字号、行距、字体、高亮颜色设置；用户已调整的值优先，不覆盖已有偏好。未另加排版偏好字段，也未改变已有字号/行距范围。
- 切换样式后重新计算当前句位置，保持当前音频进度；不 seek、不重启播放。
- 普通点击仍回到封面，仅手动浏览选中的歌词可定位播放。时间标签仍只在浏览时出现，长句换行和大字体继续按实际文本高度定位。
- 选择保存在原本机装扮偏好中，重启可恢复。未知值及旧偏好继续回到原有默认样式。

同时为“我的风格”的两处开关提供透明 Material，避免页面有色内容层挡住 ListTile 的墨水效果；没有新增背景或更改其他页面的主题。

## 验证与发布边界

路由测试在强制横向页面主题下核对进出过程坐标、播放器静止和返回；手势测试继续覆盖歌词禁用、滑块横拖、重复进入和取消。歌词测试核对无启用模糊滤镜、居中、长句、大字体、自定义排版、切换样式、选句播放及偏好恢复。补跑评论预加载/发评及装扮窄屏/大字体布局回归，合计 54 项通过；对所有改动 Dart 文件静态分析无问题。

预览 PNG 为 Flutter 组件实渲染，使用测试歌词及本机字体；不代表 Android 实机验收。本轮未打包 APK、不提升版本号、不改 SDK 或下载传输。合并后由作者使用原有发布环境打包，实机确认底部评论动画和歌词视觉。

本机复用现有 Flutter 3.47.7 隔离依赖配置进行 --no-pub 验证，未提交锁文件或依赖更新。上游继续使用作者既有构建环境。
